# ADR-011 — Conditional PostgreSQL inside the managed sandbox

**Status** Accepted in architecture baseline v1.1. Refines ADR-003.

**Context.** OrderFlow requires PostgreSQL. Other assessments can use a file-only workspace. An external shared database increases network permissions and cross-attempt exposure.

**Decision.** Start a dedicated supervised PostgreSQL instance inside the managed sandbox only when the manifest declares the service. Bind it locally, use attempt-scoped credentials, migrate and seed before readiness, and terminate it with the sandbox. Grant the candidate no platform database access.

**Alternatives.** An external per-attempt database adds cross-boundary connectivity. Unconditionally launching PostgreSQL consumes resources for packages that do not use it.

**Rationale.** Co-locating the declared service with the attempt makes its security boundary, lease, and destruction explicit.

**Consequences.** A source seal preserves files for grading. A recovery checkpoint for PostgreSQL must also preserve transaction consistency. A raw filesystem copy during writes is insufficient.

**Validation.** Check both manifest variants, service independence from the PTY, migrations and scoped privileges, recovery during active writes, and destruction when the lease expires.
