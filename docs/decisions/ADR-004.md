# ADR-004 — Provider-neutral AI gateway

**Status** Accepted in architecture baseline v1.1.

**Context.** Independent and AI-assisted work must be evaluated separately. Context files and model responses can contain untrusted instructions.

**Decision.** Route platform AI access through a trusted gateway. Resolve authorization, stage, model, context, permitted tools, and budgets on the server. Begin with one approved model, read-only context, and suggested changes. Keep provider credentials in the control plane.

**Alternatives.** Browser-to-provider access exposes credentials or bypasses controls. Coupling orchestration to one model SDK makes substitution and auditing harder.

**Rationale.** One enforcement point can reject Stage A requests before dispatch and attribute authorized Stage B usage to the attempt.

**Consequences.** Provider failures, rate limits, concurrent budget consumption, interaction retention, and model versioning require explicit handling.

**Validation.** Exercise direct API calls during Stage A, unauthorized context requests, provider failures, budget races, and evidence capture using synthetic interactions before processing candidate data.
