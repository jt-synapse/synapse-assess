# ADR-002 — Monaco and xterm.js

**Status** Accepted in architecture baseline v1.1.

**Context.** Candidates edit several files, run structured tests, and use an interactive terminal. The sandbox filesystem owns the working copy.

**Decision.** Render files with Monaco and the sandbox PTY with xterm.js. Use revision-aware saves and broker-issued, short-lived, single-use terminal tickets bound to the attempt and sandbox. Structured runs record the revision actually executed.

**Alternatives.** A hosted general-purpose IDE introduces its own authorization surface. A single text box does not support the required workspace.

**Rationale.** The platform can integrate editor state, stage permissions, and evidence while controlling what is visible to the candidate.

**Consequences.** The application owns buffer recovery, conflict handling, accessible navigation, and PTY revocation.

**Validation.** Save concurrently through the terminal and editor, reconnect with dirty buffers, run the saved revision, and verify ticket expiry, replay rejection, cross-session rejection, and stage-end revocation.
