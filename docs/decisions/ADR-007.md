# ADR-007 — Server-authoritative session lifecycle

**Status** Proposed for formal ratification. Server enforcement is required by the project security contract.

**Context.** Candidate requests, server deadlines, worker retries, and infrastructure failures can coincide.

**Decision.** The control plane owns transitions, deadlines, permissions, and version pinning. Enter a sealing state, revoke mutation access, finish accepted writes, persist and verify the formal snapshot, then activate the next stage. Commit transition facts and their evidence transactionally.

**Alternatives.** Client clocks or unconditional next-stage requests let reconnects and retries change the meaning of a completed stage.

**Rationale.** A recoverable intermediate state preserves independent work before new permissions take effect.

**Consequences.** Each transition requires authorization, idempotency, and concurrency control. Disconnection and confirmed infrastructure failure must be distinguishable under the approved recovery policy.

**Validation.** Race a deadline with manual completion, retry after a worker crash, fail snapshot persistence, and verify that no new stage permissions are granted until the seal is durable.
