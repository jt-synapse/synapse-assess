# ADR-001 — Managed execution sandboxes

**Status** Accepted in architecture baseline v1.1.

**Context.** The browser and the code an assessment participant writes or uploads are untrusted. An attempt needs a long-running terminal, bounded resources, and recoverable files.

**Decision.** Give each attempt its own managed isolated sandbox. A trusted execution adapter owns provisioning, health checks, files, commands, terminal attachment, snapshots, restoration, and termination. Apply resource limits, deny-by-default networking, an owner, and an expiration lease before accepting work.

**Alternatives.** A control-plane subprocess shares host access. Operating a dedicated isolation platform would add a security and operations team dependency.

**Rationale.** The adapter lets the platform test a provider's actual isolation and lifecycle guarantees against the assessment workload.

**Consequences.** Provider selection depends on SB-001. A reconciler must reclaim partially provisioned and expired resources. Local test doubles can verify protocol behavior only.

**Validation.** Benchmark both shortlisted providers, including long-lived PTYs, quotas, privilege boundaries, interrupted provisioning, restore, and repeat cleanup. Record the selection separately with the measurements.
